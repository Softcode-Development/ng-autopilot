# spartan/ng + Tailwind

Library-specific half of the design discipline; the project's `docs/DESIGN_SYSTEM.md` holds the catalog and the tokens. **Component APIs, composition, forms, icons and styling rules come from the official spartan skill (`.claude/skills/spartan`) and the spartan MCP server** — this rule adds only what is specific to the autopilot workspace.

- **Two layers:** `@spartan-ng/brain` (headless, accessible primitives, from npm) and helm (the styled layer, generated by spartan's CLI into the path `components.json` names and owned by the project). Every interactive element uses them.
- **Audit authority:** the spartan MCP server (runs the installed brain version), then `https://www.spartan.ng/components/{name}`. A listing of `node_modules/@spartan-ng/brain` or of the local helm folder is not an audit.
- **Adding a primitive:** `ng g @spartan-ng/cli:ui --name={name} --interactive=false` (Nx: `nx g`); it reads `components.json` and wires the `@spartan-ng/helm/{name}` path. Never copy helm code from the docs by hand.
- **Generated code is vendor code:** listed in `lint.vendorGlobs`, so the strict lint and the stylesheet rule skip it; it is still type-checked. Change it through the CLI (`ng g @spartan-ng/cli:healthcheck --autoFix`, the migration generators); a deliberate local change to a helm file is recorded in `docs/DESIGN_SYSTEM.md` § 3 so a regeneration does not silently drop it.
- **Visual style:** `"style"` in `components.json` (the default design uses `nova`). spartan writes the style's classes into each generated component; switching style = regenerating the components.
- **Legacy setup** (`design.legacyCss`): after every `ui` run, `node tools/autopilot/spartan/prefix.mjs <helm path>` prefixes the generated classes with `tw:` (and makes `hlm()` merge prefixed classes); `src/styles/spartan-preset.css` is spartan's preset with its `@apply` prefixed — re-create it with `node tools/autopilot/spartan/spartan-css.mjs preset src/styles/spartan-preset.css` after a spartan upgrade. — **Enforcement:** doctor reports unprefixed generated classes and a stale preset copy.
- **Tokens:** semantic CSS variables (OKLCH) on `:root` / `:root.dark`, generated into `src/styles/tokens/colors.css` by `ng g @spartan-ng/cli:ui-theme` and trimmed by `spartan-css.mjs tokens` — never edited by hand. Project tokens: `src/styles/tokens/app.css`, the `--app-*` namespace with `-foreground` pairs. Brands (`design.brands`): `src/styles/brands/{name}.css` overrides only what differs, under `.brand-{name}`.
- **Dark mode:** class `dark` on `<html>` (the spartan preset's `dark` variant).
- **Versions:** `@spartan-ng/brain` / `cli` / `mcp` and `@angular/cdk`, `@ng-icons/*` follow the project's Angular major; the other spartan peers resolve to the newest version the installed brain accepts — never pinned (`spartan init` pins `@angular/cdk` exactly; install re-resolves it).
- **Nx workspaces:** the generator may emit a broken `@nx/enforce-module-boundaries` entry in a per-primitive `eslint.config.mjs`; delete that key — the rule inherits from the base config.
